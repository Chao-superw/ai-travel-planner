## 邮箱认证专项验证

- 真实 PostgreSQL 服务测试覆盖验证码次数/过期/重放、成功重发使旧码失效、失败发信保留旧码、重复邮箱不能覆盖密码、6 路并发注册仅一次成功、重开连接后限流和错码计数仍有效。
- 旧用户名账号通过验证绑定邮箱后保留 ID、密码、角色和行程归属；绑定前业务受限、绑定后旧用户名登录失效。跨账号 proof 互换被拒绝，同账号并发绑定两个邮箱只有一次成功，账号写入失败会回滚验证码消费。绑定链路由真实数据库服务测试和网关映射测试验证，未另做浏览器 UI 测试。
- 独立复审发现被限流账号可继续消耗共享额度的问题；先复现失败回归，再将拒绝路径改为全事务回滚，登录/发信两项配额保护回归通过。已获准的错误密码与错码请求仍计入限额。复审没有发现剩余阻塞项。
- 迁移测试从旧 users/trips 结构升级，确认原账号、密码摘要、角色与行程版本/归属不变。初期重复执行 DDL 曾与业务写入形成锁冲突；修复 DDL 顺序并记录迁移版本，重新迁移不再阻塞已有 users 表的读锁。
- SMTP 测试验证 TLS 证书、认证、协议失败与超时、注入拒绝和日志脱敏；只使用本地接收器，不代表 QQ 实际投递和收信验证。
- 本机运行中的 API/Travel 已更新，`/readyz` 成功；新发码接口无效邮箱返回 400 `INVALID_INPUT`，并带 `Cache-Control: no-store`。保留原 Planner 和 PostgreSQL，未向真实邮箱发信。
- SMTP 授权码和 HMAC 密钥仅存于忽略的本地 `.env`（权限 0600）；源码/文档扫描未发现这些认证密钥。完整竞态测试、静态检查和本机编译日志分别在 `.local/email-auth-race.log`、`.local/email-auth-vet.log`、`.local/email-auth-build.log`。

公交独立适配复验发现，真实 v5 公交的 buslines.polyline 和 walking.steps.polyline 使用嵌套 `{polyline: string}` 对象；早期 fixture 只覆盖字符串。用人工公开坐标获得 23,585 字节的官方成功响应，并据此补充嵌套结构、步行/公交顺序和备选线路回归测试。

修正后的真实公交适配器独立调用通过：4,688 米、2,470 秒、200 分，折线 2,813 字节。仅当公交明确无方案时允许实查短步行（至多 1,500 米且至多 1,500 秒）；网络、鉴权和配额故障不触发该策略。自动测试验证阈值、调用次数、缓存/历史复用提示和错误分类；明确无路线不缓存虚构路线，不会作为成功计划保存。

上述耗时是本次样例值，包含排队与执行，不能作为服务时延承诺。最终两次生成均不需要模型修复，整日重规划使用了一次修复；每个任务都遵守最多两次模型调用的上限。源码/文档/配置与运行日志扫描共 135 个文件，未检出用户提供的两项供应商凭据。

真实整日重规划成功不代表所有下午窄范围修改都能成功。实际下午样例返回 `SCOPE_CONFLICT`，前端应展示具体原因并由用户重新选择范围；受控 E2E 的下午修改成功则证明契约、范围保护和保存链路。早期失败记录全部保留。
